# 项目术语表

本文件解释项目中反复使用的术语，供客户与团队对齐，也供接手的 AI Agent 快速理解上下文。

---

## MVP（Minimum Viable Product，最小可行产品）

**定义**：能用、能交付给真实用户、能验证核心价值的最小功能集合。

**关键点**：

- MVP **不是"半成品"或"阉割版"**，而是一个**完整可用的产品**——它把核心链路端到端打通，用户可以真正拿它干活。
- MVP **不是"功能越少越好"**，而是"**围绕核心价值，砍掉非必要的边缘功能**"。
- MVP 的目的是**尽早验证方向**：先让用户用起来，收集反馈，再决定后续投入方向，避免一次性做完所有功能却发现方向错了。
- MVP 之后进入**迭代**：按优先级逐步补齐二期、三期功能。

**在本项目中的含义**：

mf-perch 的核心价值是"**让 AI Agent 通过 SSH 操作管理主机，人类可管可控可审计**"。因此 MVP 必须完整包含：

1. 人类能添加主机、配置认证信息；
2. 人类能启停 MCP Server；
3. Agent 能列出主机、创建终端、执行命令（同步 + 异步）、查询状态、归档终端；
4. 人类能查看终端、审计命令历史、删除终端。

**MVP 不包含**（二期及以后）：SFTP、端口转发、数据备份与同步（Q32）、**自动下载 / 安装更新**（D23：一期只做版本检查 + 提示到 Release 页手动下载）、长命令完成通知（D22：一期只做应用内状态更新）、macOS/Linux 构建（D8：首发仅 Windows，跨平台构建配置预留但暂不启用）等。

> **sudo 提权不在此列**：Q33 已决定 `deny` / `ask` / `auto` 三模式**一期全部实现**，
> 并已按 D47 / D48 / D49 落地为"双通道 + `run_as_root` 工具"
> （见 [`design/sudo.md`](design/sudo.md) §0；**D60 起增第四档 `not_needed`**）。它与"核心链路"直接相关——
> Agent 要装包、改配置就得提权，因此不能留给二期。

**判断标准**：如果某个功能砍掉后，"Agent 能安全地通过 SSH 操作主机、人类能审计"这个核心闭环依然成立，它就不进 MVP。

## 其他术语

| 术语 | 含义 |
| ---- | ---- |
| **SSH 主机** | 目标服务器信息（地址、端口、名称），有唯一 ID |
| **认证信息** | 用户名 + 密码 / 用户名 + 私钥，有唯一 ID，可被多个主机引用；对 Agent 不可见 |
| **SSH 终端** | 绑定到某主机的一条常驻会话，Agent 用它执行命令；人类只读可审计、可删除 |
| **归档终端** | 关闭会话但保留命令历史；归档后 Agent 不可见，人类仍可审计 |
| **MCP Server** | 应用内嵌的 MCP 协议服务，Agent 通过它操作终端 |
| **Streamable HTTP** | MCP 的 HTTP 传输方式，本项目采用的唯一传输 |
| **TOFU** | Trust On First Use，首次连接即信任并记录主机密钥 |
| **ADR** | Architecture Decision Record，架构决策记录，见 `docs/decisions.md` |
| **MCP 工具** | Agent 可调用的操作，如 `run_command`、`get_command_status` |
