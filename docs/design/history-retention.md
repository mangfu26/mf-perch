# 命令历史保留策略

> 状态：待客户确认（对应问题清单 Q12）
> 客户决策方向：**按时间保留**（默认 30 天，可配置），**不设条数上限**，理由是执行命令属高危操作，历史必须完整保存。

## 1. 客户意见与评估

### 1.1 客户意见

- 只保留最近 30 天，用户可配置留存时长，可能细化到小时或分钟。
- **不限制条数**，不应"超过多少条就自动删除"。

### 1.2 团队评估：认同核心判断

"按条数截断"确实不适合审计场景：条数上限与时间无关，可能把昨天刚发生的关键操作删掉，而保留了大量无关紧要的旧记录。**按时间保留更符合审计直觉**（"保留最近 N 天"是明确的政策），因此采纳时间维度。

同时需向客户明确一点：**按时间保留同样会删除历史**（超过保留期的记录会被清理）。若目标是"永不丢失"，应选择"永久保留"并配合备份（Q32）。二者是不同取向，客户可自行选择。

## 2. 建议的保留策略

### 2.1 保留期设置

| 项 | 建议 |
| ---- | ---- |
| 默认保留期 | **30 天** |
| 可配置范围 | **1 小时 ~ 永久** |
| 可选单位 | **小时 / 天 / 周 / 月** |
| 永久保留 | 提供"永久保留"选项（保留期 = 永不清理） |

**不建议支持"分钟级"保留期**，理由：

1. **违背审计目的**：保留期短到分钟，历史几乎立即消失，等于没有审计能力；
2. **易误配置**：用户想设 30 天却误设为 30 分钟，会造成不可恢复的数据丢失；
3. **清理频率问题**：分钟级清理需要高频任务，收益极低、开销与风险都上升。

若客户确有"频繁清空"的隐私需求，建议作为**独立的"立即清空历史"手动操作**提供，而不是靠短保留期实现。

### 2.2 清理机制

- **触发时机**：应用启动时执行一次，之后每 24 小时执行一次。
- **清理动作必须留痕**：记录清理时间、删除条数、时间范围到"维护日志"，使"删除"这一行为本身可审计。
- **不做静默后台删除**：清理前后在设置页可见（如"上次清理：2026-09-09 10:00，删除 128 条"）。
- **短保留期告警**：若保留期 < 24 小时，设置页给出明确警告。

### 2.3 磁盘占用与体量控制

按时间保留时，磁盘占用取决于**命令输出体积**，而非条数。给出量级参考：

| 场景 | 日均命令数 | 平均输出 | 30 天占用 |
| ---- | ---- | ---- | ---- |
| 轻度 | 100 | 2 KB | 约 6 MB |
| 中度 | 500 | 10 KB | 约 150 MB |
| 重度（构建日志等） | 500 | 500 KB | 约 7.5 GB |

因此建议：

1. **单条输出上限**（Q4 已定，默认 1 MB / 20000 行），超出截断并标注 `truncated`；
2. 设置页展示**数据库当前体积**与**历史记录占用**；
3. 超过阈值（建议 500 MB）时**提示用户**，并引导"导出后清理"；
4. 提供**手动清理**入口：按时间清理、清空全部历史（均需二次确认）。

### 2.4 与终端生命周期的关系

| 情形 | 历史处理 |
| ---- | ---- |
| 终端归档 | 历史保留，仍受保留期约束；归档终端对 Agent 不可见，但人类仍可审计 |
| 终端被人类删除 | **历史一并删除**（Q19 已定，属用户主动操作） |
| 主机被删除 | 其下终端与历史一并删除（需二次确认） |

> 待客户确认：归档终端的审计记录是否希望**豁免保留期**（即永久保留）？审计视角下，归档终端往往正是需要长期留存的证据。

## 3. 已确认结论（Q12，2026-09-09）

1. **采纳按时间保留**：默认 **30 天**，可配置，范围 **1 小时 ~ 永久**，单位 **小时 / 天 / 周 / 月**。
2. **不支持分钟级**，**不提供"立即清空"按钮**。客户判断无必要：磁盘占用高时，用户手动删除归档终端即可释放。
3. **归档终端的历史永久保留**，除非用户手动删除该终端。理由：审计需要。
4. **不设条数上限**（客户明确：高危操作必须完整保存，不因条数自动删除）。

### 3.1 保留期适用范围（据上述结论推导，客户已明确确认）

| 终端状态 | 历史保留行为 |
| ---- | ---- |
| **活跃终端** | 受保留期约束（默认 30 天，超期清理） |
| **归档终端** | **豁免保留期，永久保留**，直到用户手动删除该终端 |

> 客户确认原话：用户设定的期限是约束活跃的未归档终端，已归档的应该永久保留，直到被手动删除。

### 3.2 清理机制

- **触发时机**：应用启动时执行一次，之后每 24 小时执行一次。
- **只清理超期的活跃终端历史**；归档终端历史不参与清理。
- **清理必须留痕**：记录清理时间、删除条数、时间范围到维护日志，使"删除"行为本身可审计。
- **不做静默后台删除**：设置页展示"上次清理"信息。
- **短保留期告警**：保留期 < 24 小时时，设置页给出警告。

### 3.3 磁盘占用控制

- **单条输出上限**（Q4 已定，默认 1 MB / 20000 行），超出截断并标注 `truncated`。
- 设置页展示**数据库体积**与**历史记录占用**。
- 占用偏高时的引导：**由用户手动删除不需要的归档终端**（客户选择的方式），不做自动删除。
- 提供"按时间清理"为自动策略，不提供"立即清空全部"按钮。

### 3.4 与终端生命周期的关系

| 情形 | 历史处理 |
| ---- | ---- |
| 终端归档 | 历史**永久保留**，对 Agent 不可见，人类仍可审计 |
| 终端被人类删除 | **历史一并删除**（Q19 已定，用户主动操作） |
| 主机被删除 | 其下终端与历史一并删除（需二次确认） |
