# D3 — 终端会话模型：常驻会话 + NUL 分帧 + 标记判定

> 日期：2026-09-09  索引：[decisions.md](../decisions.md)
> 状态：现行（若与代码冲突，以代码与索引中标注的取代关系为准）。


- **日期**：2026-09-09
- **决策**：采用设计文档 [`docs/design/terminal-session.md`](../design/terminal-session.md) 中的"方案 C"。
  1. 终端为**常驻 SSH 会话**，保留工作目录与环境变量；**不申请 PTY**。
  2. 命令通过 SSH channel stdin 以 **NUL 字节（`0x00`）分帧**传输，远端用 bash 内建 `read -r -d ''` 读取后 `eval`；**不依赖 base64 或任何外部命令**。
  3. 命令结束由远端脚本自打印的带随机 nonce 的标记行判定，输出边界明确。
  4. 不支持交互式全屏程序；远端需具备 bash，创建终端时探测。
- **背景**：
  - 客户希望 Agent 像人类一样操作终端，需要保留状态（方案 A 体验最好但依赖提示符识别，不可靠；方案 B 无状态但不像终端）。
  - 客户指出 base64 未必安装在目标主机，架构师改用 NUL 分帧（`execve` 参数以 NUL 结尾，命令不可能包含 NUL），彻底消除该依赖。
- **影响**：
  - `vim` / `top` / `less` 等需 PTY 的程序不可用——符合"Agent 不应做交互式操作"的定位。
  - 单条命令卡死时 MVP 只能终止整个会话；精细化 kill 留待二期。
  - 远端 bash 依赖需在创建终端时探测并明确报错。
