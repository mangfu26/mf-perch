# D42 — 更新源内置默认地址（仍可被用户覆盖）

> 日期：2026-09-12  索引：[decisions.md](../decisions.md)
> 状态：现行（若与代码冲突，以代码与索引中标注的取代关系为准）。


- **日期**：2026-09-12
- **决策**：
  1. 内置默认更新源（客户维护的 Gist 清单）：
     `https://gist.githubusercontent.com/mangfu26/311c09b123911b6a4860483a645a4eb0/raw/mf-perch-update.json`；
  2. 设置页「更新源地址」显示**生效值**（默认或用户自定义），可覆盖，
     并提供「恢复默认」（清空自定义即为回退）；
  3. `UpdateInfo` 增加 `source_is_custom`，界面据此提示"当前使用内置默认地址"；
     默认地址只在 Rust 侧维护一处，不复制到前端。
- **背景**（客户反馈）：默认值为空导致两个问题——用户**不知道该填什么**，
  且自动检查从不生效，等于"更新功能默认不存在"。
- **为什么用不带修订号的 raw 地址**：`.../raw/<文件名>` 始终返回最新修订，
  因此**只改 Gist 内容就能让所有用户收到更新**；带 SHA 的形式钉死在某一版。
  两种形式**均已实测**返回 200 且不跳转（应用禁用了跟随重定向，会跳转的地址会直接失败）。
- **代价（明确接受）**：内置默认值**只能在发新版时修改**——地址真要变时，
  老版本用户需手动改设置。因此约定：Gist 地址一旦发布就不换，只改内容。
- **顺带修正的文档**：`docs/update-manifest.md` 原写"留空即完全关闭自动检查"，
  现在语义变了——留空等于用内置默认，关闭检查请用「自动检查」开关。
- **验证**：用应用自身的抓取代码实测客户 Gist——200、可解析、平台键
  `windows-x86_64` 存在、首发场景判定为 `UpToDate{0.1.0, 0.1.0}`（不误报更新）。
- **相关**：D23（更新检查机制）、Q34（客户选 Gist）。
