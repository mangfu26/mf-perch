# D48 — 提权取数：按需在数据面探测一次当前目录（回复按命令号归属）

> 日期：2026-09-16  索引：[decisions.md](../decisions.md)
> 状态：现行（若与代码冲突，以代码与索引中标注的取代关系为准）。

> 条目自述状态：已定稿并实施（取代 D47 中"cwd 取数"那一节的早期设想）。


- **日期**：2026-09-16
- **状态**：**已定稿并实施**（取代 D47 中"cwd 取数"那一节的早期设想）。
  2026-09-16 收网审计发现本条原文内部矛盾（正文写"应用内部命令不进历史"、
  落地段写"会写进命令历史"，而代码是第三种形态），经客户确认**按代码定稿**——
  见下方"落地形态"与"关于'应用内部命令'这个概念"。
- **背景（客户指出 D47 的缺口）**：D47 原定 cwd 取数用"往数据面发一条探测帧"。
  实施时发现两处障碍：
  1. **数据面输出的读端只有一个消费者**（`terminal/mod.rs` 的输出泵，
     且 `rx` 是单消费者 `mpsc::Receiver`，在注册时被 move 进去）。
     探测帧的回复没有归属位子——输出泵只把每一行挂到"当前正在执行的那条命令"上，
     没有当前命令就**直接丢弃**。所以应用"问得出去、听不回来"；
  2. **改成"远端随每条命令收尾自报目录"也不成立**：它是**被动**取数，
     前提是"至少跑过一条普通命令"。若 Agent 的**第一条命令就是提权**，
     面板手上一个目录值都没有（客户称之为冷启动缺口）。
- **决策（客户方案）**：把归属规则从"只认当前那一条命令"扩展为
  **"按命令号把回复交给等它的那个人"**——应用生成一个命令号、把探测命令按正常
  帧格式下发，输出泵按命令号把回复交回发起方。三条约束：
  1. 探测**不进命令历史**、不出现在 Agent 可见面、不发 Agent 事件
     ——它不是"D47 早期被否掉的幽灵命令"（那种会出现在 Agent 的历史里）；
  2. 探测与 Agent 命令**共用同一把执行锁**：串行语义不变，任一时刻
     一个终端只有一条命令在跑；发起探测时必须持有执行锁，
     否则两边的输出会串在一起（实测形态：紧随提权之后的普通命令被探测
     覆盖成"退出码未知、输出为空"，而远端其实已执行完）；
  3. 取数**按需**发生，不依赖"是否跑过命令"，因此没有冷启动缺口。
- **为什么比 D47 的设想更好**：
  - **没有冷启动缺口**：按需主动取数，第一条命令就提权也成立；
  - **不动既有协议格式**：不需要把目录塞进结束标记（那条路要改解析器与全部 e2e 断言，
    且路径可能含 `__` 或换行）。
- **落地形态（R3 实现，经客户 2026-09-16 确认按此定稿）**：
  `TerminalRuntime::run_as_root` 在**持有执行锁**的前提下，先经
  `probe_data_plane_cwd` 在数据面发一条普通的取目录命令
  （`printf '%s' "$PWD"`，应用生成命令号、按该号收回输出），
  **不写命令历史、不发 Agent 事件**——它属于应用内部取数，不是 Agent 的命令；
  随后建立特权通道，在**一次提权内连着**执行
  「`cd <目录>` + `echo $EUID` 核实身份 + Agent 命令」，最后收掉特权通道。
  提权命令**本身**照常进历史（带 `[特权用户(uid=0)]` 前缀），因此人类事后仍能
  看到"哪条命令以特权身份、在哪个目录下执行"。
- **关于"应用内部命令"这个概念（2026-09-16 收网澄清）**：
  本条最初设想引入一层通用的"应用内部命令"通路（让面板能问远端任何一句话）。
  实现时**没有引入这层抽象**：探测直接走既有的正常通路 + 按命令号配对，
  代码里不存在"内部命令"这一类型或概念。**该概念已废弃**，
  将来若真出现第二个"面板想问远端一句"的用途，再另立决策评估是否值得抽这一层。
- **实现中修正的两处偏差**：
  1. **实际 uid 必须核实**：不能因为"提权成功"就标注 `uid=0`——sudoers 可以配置成
     `user ALL=(someuser) ...`，此时 sudo 成功但落到非 0 用户。因此在同一次提权里
     打印 `${EUID}`，由 `protocol::take_privileged_identity` 摘出；非 0 时在输出开头
     明确告警，返回结构里如实给出 `actual_uid`（审计不写假话）；
  2. **提权帧必须发到特权通道**：编排早期版本误用数据面的 session 发送该帧，
     那会让"提权命令"以登录用户身份执行——**看起来成功、实际没提权**。
     已在代码中留注释，并由 e2e 断言 `actual_uid == 0` 守住。
- **审计口径（客户确认）**：命令历史里以文本前缀 `[特权用户(uid=0)]` 标记，
  不改数据库结构、不改前端契约（方案 A）；"独立字段 + UI 标签"作为后续可选升级。
