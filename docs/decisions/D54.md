# D54 — 发布流水线：tag 触发构建 Windows 安装包并挂载到 GitHub Release

> 日期：2026-09-19  索引：[decisions.md](../decisions.md)
> 状态：现行

- **日期**：2026-09-19
- **决策**：`.github/workflows/release.yml` 是本项目的发布流水线，其现行事实：
  - **触发**：推送匹配 `v*` 的 tag；另留 `workflow_dispatch`（手填已存在的 tag）用于
    构建失败后重跑，避免"删掉 tag 再重打"；
  - **平台与产物**：只构建 Windows（`windows-latest`），因 `bundle.targets = "all"`
    一次产出两类包，Release 同时挂 `bundle/nsis/*.exe` 与 `bundle/msi/*.msi`；
  - **工序**：先校验 tag 版本等于 `tauri.conf.json` 的 `version`，再跑
    AGENTS.md §5.10 的五道默认门禁，然后 `pnpm tauri build`，最后创建 Release 并上传，
    `fail_on_unmatched_files: true` 使"少一个包"直接判红；
  - **不自动写更新清单**：CI 只把真实的文件名 / size / SHA256 写进 Release 正文供人抄，
    Gist 仍由人工改（源与取舍见 **D23 / D42**）；
  - **不做代码签名**：Release 正文固定声明"未签名 → 首次运行有 SmartScreen 提示"；
  - **不跑 `#[ignore]` 的真实环境 e2e**：那些用例依赖 WSL 里的 SSH 服务器（**D27**），
    按 AGENTS.md §5.11 仍由本地在推送 / 并入 `main` 前执行。
- **理由**：
  - **版本校验**：安装包文件名里的版本来自 `tauri.conf.json`，Release 下载 URL 里的版本
    来自 tag。两者不一致时，挂出的包是 `0.1.0` 而清单指向 `v0.2.0` 的路径，用户点下载
    就是 404。校验把 `docs/update-manifest.md` §5 的"人工核对文件名与 tag"变成机器拦截。
  - **不把写 Gist 的凭据交给 CI**：更新清单是**信任锚点**——它决定向全体用户推送哪个
    下载地址。现在"仓库凭据"与"Gist 凭据"是两套独立钥匙；合并成一把之后，
    "能触发这条流水线"就等于"能向全体用户推更新"，属供应链攻击面（与 **P3** 关注的
    "绿灯不等于属性成立"同源）。换来的收益只有一次粘贴操作，故不做。
    将来若要全自动，应挂在**单独的手动 `workflow_dispatch` 发布 job** 上，
    让"出安装包"与"推更新提示"保持为两个独立授权动作。
  - **只构建 Windows**：其余平台的 runner 各自需要额外工具链与打包依赖，
    在未验证前先不摊开（首发平台见 **D8**）。
- **已知边界（对外说明前看这里）**：
  - **触发器无法限定分支**：Git 的 tag 是独立 ref、不属于任何分支，`on.push` 的
    `branches` 过滤对 tag 事件无效，同时写 `branches` 与 `tags` 只会让语义互相干扰。
    "tag 从 `main` 打" 由 AGENTS.md §1.1 / §1.5 的人工纪律保证；仓库层的硬约束是
    GitHub 的 **Rules for tags**（设置项，不在本文件职责内）。
  - **流水线尚未真机验证**：提交前只做了结构检查（缩进 / 重复键 / 块标量）与两段 `pwsh`
    步骤的 PowerShell 语法解析，**YAML 整体未经 Actions 实际执行**。首次发布以第一次
    CI 运行为准。
  - **生效前提**：这个文件必须先随 `main` 推送到远端，且 tag 打在包含它的提交上——
    Actions 只在 tag 指向的那个提交里找 workflow 定义（远端当前状态见 AGENTS.md §3）。
- **影响**：
  - 发布流程 = 打 tag → 流水线出包并建 Release → 人工改 Gist 清单；
  - `docs/update-manifest.md` §5 的 `sha256` / `size` 取法以该版 Release 正文为准，
    本地构建命令降为备用；
  - 未改动任何运行时代码，`tauri.conf.json` 与构建脚本保持原样。
- **相关**：D23 / D42（更新源与人工维护清单）、D8（首发平台）、D27（真实环境测试边界）、
  D51 / P4（构建遇阻禁止绕过）、P3（安全属性须可验证）、D53（本条只记现行事实的写法依据）。
