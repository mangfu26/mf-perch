# D56 — 主机与凭据的写入操作要求主密钥已解锁（不做延迟取密钥）

> 日期：2026-09-20  索引：[decisions.md](../decisions.md)
> 状态：现行。

- **背景**：修复 v0.1.0"无法添加 SSH 主机"时（错误被吞的成因见
  [`design/principles.md`](../design/principles.md) **P5**）暴露出一个范围问题：
  错误一旦如实透出，K2（主密码）用户在**未解锁**状态下点保存会收到
  "凭据尚未解锁，请先在应用中输入主密码"，功能看起来仍然"加不了主机"。
  备选方案是**延迟取密钥**：把 `master_key(state)` 从函数入口下推进到真正需要加/解密的分支，
  使"不绑凭据、不设独立 sudo 密码"的主机能在未解锁时保存。
- **决策（客户 2026-09-20）**：**保持必须先解锁**。`save_host` / `save_credential`
  在入口处取主密钥，未解锁一律明确报错。
- **理由**：保存主机要么需要解密所绑凭据（校验其类型能否用于提权），要么需要加密
  `sudo_password_enc`，两者都是常规路径而非边角；延迟取密钥只会放行
  "能保存但保存得不完整"的中间态——提示更难解释，
  还让凭据边界（D6）的成立与否取决于调用路径。解锁是本应用的常规前置动作，
  不是异常分支。
- **护栏**：不要为了"未解锁也能加主机"把入口处的 `master_key(state)` 下推进分支；
  同理不要在未解锁时静默跳过凭据校验或 sudo 密码加密（P2）。
