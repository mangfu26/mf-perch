# D57 — 现行文档不登记可由代码或测试自身导出的数量

> 日期：2026-09-21  索引：[decisions.md](../decisions.md)
> 状态：现行

- **决策**：`AGENTS.md` 与 `docs/` 的**现行**文档中不再登记"当前有多少"的可导出数量——
  测试条数、单测 / 集成规模、命令个数一类的统计数字。需要量级时用一条命令现取
  （`cargo test -j 2`、`pnpm test`、`cargo test --lib -- --list`）；
  文档只写**结构、口径与去哪看**。已写入 [`AGENTS.md`](../../AGENTS.md) §4.3（规则 8）。
- **背景**：客户 2026-09-21 明确要求。直接起因是换到新开发机后并入远端提交时，
  `docs/design/test-environment.md` §4.5 的规模表（当时写"Rust 单测 250 项 / 集成 32 项 /
  前端单测 21 项"）当场失真——远端那轮修复带进 2 条 IPC 单测与 3 条前端用例，三个数字同时过期。
  **这类数字是代码的副本**：每次增删用例都得记得回来改表，忘了就留下"看着权威、其实是错的"读数，
  比不写更糟；而测试代码加一条命令本就是事实来源（§4.1"代码能说明的不重复"）。
- **判据（一句话决定登记不登记）**：*这个数字会不会因为一次与本文档无关的提交而失真？*
  - 会 → **不登记**，改写"以 `<命令>` 输出为准"；
  - 不会 → 可以写。例如**门禁有几道**、**哪些 target 带 `#[ignore]`**、某条决策的**时间点读数**
    ——它们描述结构与当时事实，不随用例增删漂移。
- **边界（不在本条约束内，也不要顺手删）**：
  1. **快照类文档与 ADR 中带日期的实测读数**照留。它们记的是"当时测到什么"，按 §4.1 只读不追改，
     删掉等于销毁证据。例：`security-audit.md` 的通过项统计、`test-environment.md` §4.4
     的阶段一实测表、**D52** 的拆分前统计；
  2. **性能与时长类实测**属 **D53** 第 3 条的"示例依据"：保留但须带日期与取法，
     且不作为规则的适用前提；
  3. **契约与结构事实**不受影响：MCP 工具清单、target 划分、前端门禁分工，都由代码结构或
     schema 定义，不是统计计数。
- **影响**：
  - `docs/design/test-environment.md` §4.5 的规模表删除，改为"口径 + 自查命令"；
  - `AGENTS.md` §5.10 注释里的用例计数（`sudo_e2e 13 / ssh_integration 6 / mcp_e2e 4` 一类）去除，
    只留该组用例的性质与耗时提示；
  - `AGENTS.md` §4.3 新增规则 8；本机 `AGENTS.local.md`（不入库）同步去数字。
- **相关**：**D53**（三条书写规范；本条是其"代码能说明的不重复"原则对数量统计的落地）、
  **D52**（编号即外键、快照不追改）、**D27**（测试环境口径）。
