# D60 — 提权策略新增第四档 `not_needed`：登录身份已是特权用户时不走 `sudo`

> 日期：2026-09-22  索引：[decisions.md](../decisions.md)
> 状态：已实施。

- **背景（客户提出，Q42）**：认证信息里配的本就是 root 时，"提权"这一步根本不存在，
  但主机表单仍要求配置提权口令来源；`ask` / `auto` 变成无意义的必填负担。
- **关键洞察（为什么不能拿 `deny` 当答案）**：`deny` 的语义是"拒绝**提权**"，而数据面通道
  跑的就是登录身份本身——在 root 主机上 Agent 的普通命令**本来就是 root**。
  此时 `deny` 挡住的只是 `run_as_root` 这一个工具入口，挡不住任何实际的特权执行。
  把"这台机器不需要提权"表达成 `deny` 是**假的安全感**（违反 P2 的"如实"）；
  表达成 `not_needed` 才是对现状的诚实描述。
- **决策**：`SudoPolicy` 增第四档 `not_needed`（字符串 `not_needed`），并把三模式的表述
  升级为四档（**增补** D11 第 2 点）。该档的三条语义：
  1. **由人类声明，不让人填 uid**（客户 Q42 追问明确要求"开关式声明"）：
     界面上是一个策略选项，不是一个数字输入框；
  2. **`sudo_password_source` / `sudo_password` 两列一律忽略**——保存期不校验、
     运行期不取用，也**不向人类弹确认**。库里两列**不删**，切回 `ask` / `auto` 时无需重填；
  3. **特权通道不再包 `sudo`**，直接用该主机的环境加载方式起 bash
     （`privileged_launch_command()` 分档，见下）。
- **声明与核验**：声明只表达意图，**事实仍由远端核实**——身份核实
  （`${EUID}` + `id -un`，D47）在包装脚本里，与档位无关，因此声明错了（该用户实际非 0）
  仍会按现有逻辑**如实告警**，不会静默把"以为是 root"当成"是 root"。
- **数据面仍然拒绝 `sudo`（D49 不变）**，只换文案：该档下垫片提示"已以特权身份登录，
  直接执行即可"，而**不是**"改用 `run_as_root`"——后者会把 Agent 引向一条本不需要的往返。
  四档各自的拒绝理由见 `src/ssh/protocol.rs` 的 `sudo_reject_shim()`。
- **顺带的能力边界变化**：`not_needed` 不经 `sudo`，因此**少一层 `env_reset`**，
  也**不再受 `Defaults requiretty` 限制**（该选项约束的是 sudo 申请 TTY 的行为）。
  这是机制推导，**未做真实 root 登录主机的端到端实测**（见"未实测"）。
  `requiretty` 主机"不支持提权"这条对外边界**只对 `ask` / `auto` 成立**，
  已在 `AGENTS.md` §4.4 同步收窄。
- **数据库迁移（触发 D50 的条件条款）**：`SCHEMA_VERSION` 1 → **2**，`V2` 重建 `hosts` 表
  以放宽 `sudo_policy` 的 CHECK。
  - **为什么这次必须迁移**：D50 当初"刻意不迁移"的前提是**产品未发布**，
    并写明"首发前若已存在用户库，则必须改回迁移方案"。`v0.1.0`–`v0.1.2` **已发布**
    （三个 tag，见 D54 流水线），它们装出来的库全是 V1 约束，故本条起恢复增量迁移。
    旧迁移实现按 D50 的指引从 `git show 53b5621` 取回作模板，**没有重新发明**。
  - **`V1_SCHEMA` 里的 `sudo_policy` CHECK 冻结为历史形状**：放宽只由 V2 负责。
    就地改宽 V1 会让"新建库"与"存量库升级后"两种形状不一致，等于制造第二个 V1。
  - 重建表的机制、三个坑与方向选择**不在此处复述**，写在
    `src-tauri/src/store/db.rs` 的 `V2_SUDO_NOT_NEEDED` 文档注释里（实现前必看）。
    该面只记两条结论：**密文逐列原样搬运、不重新加密**；**迁移不得删掉子表数据**。
- **暂缓（不要当成已实现）**：**"运行期探到 uid=0 后反向提示人类改档"** 未做。
  保存期无法建立 SSH 连接去实测，而运行期已有的 `uid≠0` 告警覆盖了另一侧的错误
  （声明是 root 而实际不是）。等真有需求再评估，不要顺手加。
- **未实测（诚实标注）**：真实 **root 登录**主机的端到端。测试环境需要 sshd 开
  `PermitRootLogin`，属改动客户机器的事，已向客户请求授权、尚未得到答复；
  拿到授权前**不要**在测试环境自行打开该选项，也不要声称该路径"已实测通过"。
- **测试（能区分对错实现，§5.7 / P3）**：
  - `only_not_needed_launches_the_privileged_channel_without_sudo`（`ssh/protocol.rs`）——
    判别性用例：`deny` / `ask` / `auto` 三档必须**都**以 `sudo -S -p ` 开头且带上密码提示标记，
    `not_needed` 必须**既不出现** `sudo ` **也不出现**提示标记。把短路写反、或忘在某档漏掉包装，
    都会红灯；
  - `wrapper_script_always_installs_reject_shim` / `reject_shim_refuses_and_guides_to_the_tool`——
    **四档都要装垫片**（漏一档就出现"数据面能静默提权"的洞），且 `not_needed` 的文案
    不得出现"口令 / `sudo -S` / `run_as_root`"，也不得与 `deny` 文案相同；
  - `upgrading_a_v1_database_widens_the_check_without_losing_rows`（`store/db.rs`）——
    手工建 V1 库 + 一行 host / terminal / command，迁移后断言：`sudo_password_enc` **原样不变**、
    `policy` 未被重新解释、子表两条记录**仍在**（防 ① 的级联删除）、`not_needed` 写得进去、
    非法值仍被 CHECK 拒掉、`idx_hosts_credential` 仍存在（防 ③）；
  - `fresh_database_accepts_the_fourth_policy`——新建库直接认第四档（建表语句与迁移结果一致）；
  - `save_host_accepts_not_needed_without_any_password`（`ipc/tests.rs`）——
    **同一份配置**（密钥凭据 + 无任何口令）在 `auto` 档被拒、在 `not_needed` 档必须放行；
  - `serde_json_matches_as_str_for_every_domain_enum` 增补该档的字符串往返。
