# D1 — MCP Server 使用官方 Rust SDK（rmcp），仅实现 Streamable HTTP 传输

> 日期：2026-09-09  索引：[decisions.md](../decisions.md)
> 状态：现行（若与代码冲突，以代码与索引中标注的取代关系为准）。


- **日期**：2026-09-09
- **决策**：
  1. MCP Server 的协议实现使用官方 Rust SDK [`rmcp`](https://github.com/modelcontextprotocol/rust-sdk)，不自行手写 JSON-RPC 协议层。
  2. 传输方式**只实现 Streamable HTTP**，不实现 stdio。
- **背景**：
  - 客户明确要求遵循标准 MCP 规范，且指定使用官方 Rust SDK。
  - 客户不限定具体 MCP 客户端；对于不支持 Streamable HTTP 的客户端，客户接受用第三方转换工具（Streamable HTTP → stdio）接入，因此应用侧无需承担 stdio 的实现与维护成本。
- **影响**：
  - 启用 `rmcp` feature `transport-streamable-http-server`；不使用 `transport-io`。
  - 无需开发 stdio 桥接进程，架构更简单，凭据与连接池天然留在应用进程内。
  - `rmcp` 3.2.0 不含 SSE 传输 feature。若后续需兼容仅支持旧版 HTTP+SSE 的客户端，需单独评估（当前不在范围内）。
  - 协议层跟随官方 SDK 演进，我们只实现工具与业务逻辑，降低规范漂移风险。
