# D45 — ProxyJump 移出首发范围，列为未来新增功能

> 日期：2026-09-15  索引：[decisions.md](../decisions.md)
> 状态：现行（若与代码冲突，以代码与索引中标注的取代关系为准）。


- **日期**：2026-09-15
- **决策**（客户拍板）：**ProxyJump 不在首发（MVP）实现**，转为未来的新增功能计划。
- **背景 / 取代关系**：D11 / Q9 曾明确"MVP 含 ProxyJump"（理由：连内网主机是核心链路必要条件）。
  本轮盘点未处理项时重新评估，客户判断：**实际使用场景不多、也不急切**，
  故将其从 MVP 范围移出。**本决策取代 D11 / Q9 中"MVP 含 ProxyJump"的范围结论**；
  D11 / Q9 关于技术选型（russh 支持 ProxyJump 能力）的部分仍然有效。
- **当前代码状态（半成品，务必知晓）**：只做了数据管道，没有功能——
  - ✅ 数据库列 `proxy_jump_host_id`、领域模型字段、`hosts` 读写、IPC 入参/出参均已存在；
  - ❌ 前端 `HostFormDialog.vue` 无选择跳板机的控件（字段恒为 `null`）；i18n 有 `proxyJump*` 词条但无人引用；
  - ❌ 连接层完全未使用：`ssh::session::Session::connect` 永远直连 `(address, port)`，无任何跳板逻辑。
  即**目前没有任何路径能让 ProxyJump 生效**。
- **保留半成品的取舍**：现有管道字段**不删除**——将来实现时可直接复用，删了反而增加返工成本。
  但它处于"存得下、填不了、连不上"的状态，必须靠文档与 §4.4 缺口表明确标注，防止误认为已支持。
- **对外表述红线**：在真正交付前，**任何文档、界面、README、对外说明都不得声称支持 ProxyJump**。
- **影响**：
  - `AGENTS.md` §4.4 已知缺口表：ProxyJump 由"承诺未实现"改注为"已决定移出首发（D45）"；
  - `docs/open-questions.md` Q7 / Q9 及未完成项段落：指向本决策，状态改为"已决定不做（转未来）"。
- **相关**：D11（SSH 高级能力范围）、Q9（MVP 能力清单）、Q7（ProxyJump 备注）。
