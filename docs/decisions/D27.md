# D27 — 测试环境：WSL Ubuntu

> 日期：2026-09-10  索引：[decisions.md](../decisions.md)
> 状态：现行

- **日期**：2026-09-10
- **决策**：以开发机上的 **WSL Ubuntu 26.04** 作为测试目标环境，在其内运行 openssh-server
  （`127.0.0.1:2222`），Windows 侧通过**真实 SSH 协议**连接。
- **理由（为什么必须是真实 Linux，而不是进程内 mock 或容器）**：
  本项目的核心机制恰好活在"真实 shell 与真实 sshd"这一层，任何模拟都会把被测对象本身省掉：
  - NUL 分帧依赖 bash 内建 `read -d` 的实际行为；
  - 提权依赖 `sudo -S` 的 stdin 投递与 `env_reset` 语义；
  - 环境加载依赖**登录 shell**（`bash -l`）是否读 profile，即设置页的
    `shell_env_mode`（D4）——非登录 shell 下自定义 PATH 不生效，这一条只有真机能证实。
  容器内 `sudo` / systemd 行为与真机有差异，客户远端主机则不可控、无法重复搭建，故都不采用。
- **影响**：
  - 搭建步骤、环境现状与实测记录见 [`docs/design/test-environment.md`](../design/test-environment.md)
    （**本文只记决策与理由，具体读数不在这里复述**）；
  - 该环境可直接用于编码阶段的集成测试与回归验证；
  - 测试凭据（本地测试口令）为本地假值，只存在于该环境，**不入仓库**（§2.6）；
  - 老 RHEL 的 `Defaults requiretty` 等真机特例 WSL 覆盖不到，上线前建议真机抽验
    （**已知能力边界，不要当作已验证**）。
- **相关**：D3（NUL 分帧）、D4（环境加载）、D47 / D49（提权现行机制）。
