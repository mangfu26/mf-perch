# D23 — 更新检查：Gist 版本源 + 手动下载

> 日期：2026-09-10  索引：[decisions.md](../decisions.md)
> 状态：现行（若与代码冲突，以代码与索引中标注的取代关系为准）。


- **日期**：2026-09-10
- **决策**：
  1. **不做自动下载/自动安装**；仅做版本检查 + 提示用户到 Release 页下载覆盖安装。
  2. 版本信息源为 **GitHub Gist 托管的 JSON**；**源地址可配置**。
  3. 启动后后台检查（静默失败、24h 缓存）+ 设置页手动检查按钮。
  4. semver 比对、支持"忽略此版本"、自动检查可关闭、不自动打开浏览器、展示 SHA256。
- **背景**：团队建议 Releases API（零人工同步），客户基于"发布流程由自己掌控"接受 Gist 的人工同步风险，并说明流程：客户指示打 tag → 推送 → Actions 构建并创建 Release 草稿 → 客户决定发布 → 客户更新 Gist。
- **影响**：
  - 更新源抽象为可配置 URL，内部映射为统一结构，便于将来切换。
  - Gist 应在 Release 正式发布后更新，避免指向未发布页面。
- **红线**：**团队不得在客户未明确指示时创建或推送 tag**；不得自动合并到 `main`。
