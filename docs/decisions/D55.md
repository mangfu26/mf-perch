# D55 — 开源化：更新清单改为仓库文件，发布说明取自 CHANGELOG

> 日期：2026-09-19  索引：[decisions.md](../decisions.md)
> 状态：现行。


- **背景**：项目由闭源交付转为开源。原更新机制（D23）把版本清单放在人工维护的
  Gist 里，发布说明由流水线打印内部待办——两者都不适合公开仓库：
  Gist 与 Release 是两套需人工保持一致的产物（"忘记更新 Gist"是已知故障形态），
  Release 正文中的 SmartScreen / Gist 待办属内部流程信息。
- **决策**：
  1. **更新清单 = 仓库根部 `update.json`**，由发布流水线在构建并创建 Release 后
     自动生成并回写提交到 `main`（version / url / sha256 / size 全部取自真实
     tag 与真实产物，无人工誊抄环节）；
  2. 应用内置默认更新源改为
     `https://raw.githubusercontent.com/mangfu26/mf-perch/main/update.json`
     （分支引用、不钉 SHA；沿用 D42 的"可配置、可覆盖、可恢复默认"设计）；
  3. **GitHub Release 正文 = `CHANGELOG.md` 中该 tag 的小节**（Keep a Changelog
     风格，面向用户）；流水线找不到对应小节即失败——发版必须先写变更日志；
  4. 新增面向用户的 `README.md`；`LICENSE`（Apache-2.0）此前已存在；
  5. 本次迁移不改功能、不修 bug，版本号保持 0.1.0，通过重指 tag 发布。
- **取代关系**：取代 **D23 第 2 点**（Gist 版本源）与 D54 中"人工更新 Gist"的
  收尾流程；D23 其余各点（不自动安装、可配置源、静默失败 + 24h 缓存、
  semver 比对、SHA256 展示）**仍现行**。
- **红线不变**：团队不得在客户未明确指示时创建或推送 tag（D23 红线继续有效）。
- **护栏（重指 tag 的坑，2026-09-19 实测）**：删除 tag 时其 Release 会消失，但**重推同名
  tag 的瞬间 GitHub 可能把旧 Release"复活"并保留旧正文**，流水线会复用该 Release 上传
  产物——结果是新产物配旧正文（内部信息泄漏回发布页）。因此**重推同名 tag 前，必须先在
  Releases 页确认旧 Release 已彻底删除**（API `/releases` 列表为空），再删再推。
