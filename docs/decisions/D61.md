# D61 开发反馈成本治理：常驻文档分层、文档预算门禁、测试门禁分层

- **日期**：2026-09-29
- **状态**：现行
- **背景（客户 2026-09-29 提出）**：客户提出两个体感问题——"文档太臃肿，每次消耗大量 Token"、
  "每次开发都跑测试，消耗大量时间"。团队先实测再下结论，发现**成因与直觉不同**：

  1. 文档的**每次**成本不在 `docs/`（那是按需读的），而在 `AGENTS.md`——
     它被 Harness **每个请求整篇注入**，当时 25,522 字符（≈1.4 万 token），
     其中 §4（文档规则）与 §5（测试规范）合计占 63%，且大量内容是"偶尔才需要"的流程细节；
  2. 测试的**每次**成本不在用例执行，而在**依赖编译**：实测（2026-09-29，4 核 / 机械盘开发机）
     `cargo test -j 2 --lib` 冷构建 20 分钟只推进到 369 个依赖 crate、**尚未进入用例执行**；
     同期 IDE 的 `cargo check --all-targets` 冷跑也要 7 分钟以上。
     而"每次提交跑全量"这条纪律存在的根本原因，是**日常提交没有远程门禁**：
     仓库只有 tag 触发的 `release.yml`，分支 push / PR 无任何远程检查。

- **决策**：

  1. **常驻与按需分层**：`AGENTS.md` 只留"每次都可能用到"的硬规则（长度上限 8,000 字符）；
     流程细节搬进 `docs/agent/` 的按需手册（process / git / testing / test-debt / docs）。
  2. **搬迁只搬正文、不改编号**：手册沿用原章节号（§0.2–§0.5.1、§1.1–§2.5、§3、§4.6、§5.1–§5.11），
     `AGENTS.md` 保留章节骨架 + 一行转指针——仓储内既有 `AGENTS.md §X.Y` 软引用**零改动**继续有效
     （理由同 **D52** 保留 `docs/decisions.md` 路径）。
  3. **文档预算机械化**：新增 `scripts/check-docs.mjs` / `pnpm check:docs` 作为门禁——
     `AGENTS.md` ≤ 8,000 字符；`docs/**` 单文档 ≤ 12,000 字符（超限须登记白名单并写明理由）；
     `docs/` 下每个 Markdown 必须能被文档索引点中（登记文件路径，或登记其所在目录，目录须以链接形式给出）。
  4. **消两笔已登记的债**：`docs/open-questions.md` 收敛为"问题 + 状态 + 一行结论 + 指向 `D<编号>`"；
     `docs/development-troubleshooting.md` 改为**索引** + `docs/troubleshooting/` 主题分片（正文逐字搬运）。
  5. **测试门禁分层**：本地默认门禁 = `--lib --test version_check_e2e --test mcp_e2e`——
     只跳掉两个用例**全部**带 `#[ignore]` 的 target 的编译与链接，
     **执行到的用例与裸 `cargo test` 默认执行的完全一致**（`mcp_e2e` 必须留下：
     它的 401 鉴权分支覆盖是全仓唯一的一份）；全量与真实环境 e2e 只在推送 / 并入 `main` 前跑；
     新增**可复用 CI 门禁** `gate.yml`（push `develop/**`、PR → `main` 触发，`release.yml` 也 `uses` 同一份），
     使"每次提交跑全量"的动机消失。节奏表同时取代客户 2026-09-16 定的原三层节奏。
  6. **编译成本与 IDE 争用**：`[profile.dev] debug = "line-tables-only"`
     （需要完整调试信息时用 `CARGO_PROFILE_DEV_DEBUG=2` 临时覆盖）；
     `.cargo/config.toml` 只加 `[alias]`、**刻意不设 `[build] jobs`**（并行度是机器相关的，
     而 CI runner 需要默认并行度）；`.vscode/settings.json` 关闭 `rust-analyzer.check.allTargets`
     ——它会对同一个 `target` 与 `cargo test` 争构建锁，且 check 只产 rmeta、对测试毫无帮助。
  7. **修好被承诺的快路径**：给 `ipc::mcp` 模块与 7 个 IPC 命令补 `#[cfg(feature = "mcp")]`，
     使 `--no-default-features` 真能编过（此前 `Cargo.toml` 声称的"纯 SSH 引擎快速测试"实际不可用）。
  8. **门禁自身要能失败**：`check:docs` 与 `check:ipc` 均按 §5.7 精神做**差分验证**
     （注入未登记文档 / 超限文档 / 已定义未注册的命令，确认确实红灯，再确认还原后恢复绿灯）。

- **理由**：

  - **付费面不同**：`AGENTS.md` 每请求付费、`docs/` 按需付费。所以省 Token 要在常驻面下手——
    删 ADR 分片省不到那笔钱，却会毁掉记忆库与跨语言 `D<编号>` 外键（D52）；
  - **预算必须由机器执行**：文档膨胀没有编译器兜底，只有门禁能拦住（与 `check-secrets` / `check-ipc` 同一思路）；
  - **全量的价值在"没有遗漏"，不在"改这一处对不对"**：把它压在每次提交上换来的是等待而不是保证；
    CI 是"在干净机器上跑同一组检查"的合法来源（仓库 public，runner 分钟数免费）；
  - **文档规范同样要落地成检查**：`docs/agent/docs.md` §4.3 规则 9 写明口径，
    `pnpm check:docs` 是它的执行者——两者必须一致，改一处要同步另一处。

- **影响**：

  - `AGENTS.md` 25,522 → 5,482 字符（常驻 token 约减 79%），信息未丢（搬迁 + 去复述）；
  - `docs/open-questions.md` 17,381 → 4,841 字符；`docs/development-troubleshooting.md` 23,740 → 4,511 字符（索引），
    正文 22,732 字符逐字守恒；
  - 本地日常循环不再编译 / 链接 2 个"全忽略"的 test target；`check:docs` 进入 CI 门禁；
  - **顺带修好一个真实缺陷**：`scripts/check-ipc-contract.mjs` 原用"第一个 `]`"截取注册清单，
    条目一旦带属性（如 `#[cfg(feature = "mcp")]`）就会把清单截断、把其后的命令全判成"未注册"；
    已改为括号配对 + 去属性；
  - **尚未验证 / 需客户处理**：
    ① CI workflow **未推送**，未在真实 runner 上跑过；
    ② 分支保护的 required status check 需要客户在 GitHub 仓库设置里配置（显示名以首次运行为准）；
    ③ 本地与 CI 都必须先 `pnpm install`（`check:docs` 等脚本依赖 node 环境）。

- **相关**：D52（路径保留 → 软引用零改动）、D53（只写现行事实 / 环境无关）、D57 / D59（不登记可导出内容）、
  D54 / D55（发布流水线）、D51 / P4（禁止绕过构建障碍）、D1（MCP 是核心能力，故 `mcp` 特性默认开启）、
  D38（rmcp 空闲超时：`mcp_e2e` 慢用例的由来）。
