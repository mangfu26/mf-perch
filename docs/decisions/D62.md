# D62 真机测试的取值来源与客户主机的安全边界：废弃 AGENTS.local.md

- **日期**：2026-09-29
- **状态**：现行
- **背景（客户 2026-09-29 决定）**：客户要求不再用 `AGENTS.local.md` 作为"本机测试取值"的载体，
  改为：**需要真实环境测试时先问客户用哪种方式**——① 开发主机是 Windows 时用本机 WSL；
  ② 客户提供一台真实主机的连接信息。并为方式 ② 加上明确约束：
  测试命令不得越界（与测试无关的删除 / 修改 / 重命名、`kill` 其它进程、改账号密码等），
  且**每次测试结束必须清理本次产生的一切文件与数据**。

- **决策**：

  1. **废弃 `AGENTS.local.md`**：测试取值（主机 / 端口 / 用户 / 私钥 / 提权口令）**只在会话内提供**
     （环境变量，或临时放到 `.tmp-test/`），**不落本机长期文件**；`.gitignore` 中该条目随之移除
     （`.tmp-test/` 的忽略保留）。
  2. **跑真实环境测试前必须问客户选方式**（① WSL / ② 客户主机）：提问模板、可测前提写在
     [`docs/agent/testing.md`](../agent/testing.md) §5.6.1；**不许自己找一台主机试，也不许猜地址与账号**。
  3. **方式 ② 的安全边界（强制）**，落点 [`docs/agent/testing.md`](../agent/testing.md) §5.6.2：
     只用客户指定的**测试用户**；只做与测试相关的**最小动作**；禁止越界命令；
     **结束后清理本次产生的一切文件与数据**并把宿主恢复原状；需要越界时**先问客户**；
     每轮向客户回报"跑了什么 / 改了什么 / 清理了什么"。

- **理由**：

  - **取值载体落在本机文件上必然过期**：换机或重新克隆（客户本次正是删库重拉）就失效，
    而文件名暗示"这里有答案"会诱导 Agent 去猜——由客户在测试时提供是唯一不会过期的来源；
  - **客户提供的主机是别人的环境**：与团队自己起的 WSL 不同，误删无法回滚，
    所以把"最小动作 + 用完清理"写成硬约束，而不是依赖当时的临场判断
    （同类先例：D60 把"改测试机 sshd 配置"定为**需客户授权**的动作）。

- **影响**：

  - `AGENTS.md` §5 的常驻护栏改为"先问方式 + 最小动作 + 用完清理"；
    `docs/agent/testing.md` §5.6 重写（新增 §5.6.1 提问模板、§5.6.2 安全边界）；
    `docs/design/test-environment.md` 明确"本文只是方式 ① 的搭建说明"；
    `docs/troubleshooting/wsl-ssh-test-env.md` 的换机提示改指重建步骤；
  - **登记一笔测试债**：当前真机 fixture 只支持公钥认证，方式 ② 若客户只能提供口令登录的主机则跑不起来
    （见 [`docs/agent/test-debt.md`](../agent/test-debt.md) §4.6，标 **待定**，需客户拍板是否补口令路径）；
  - **D57 的影响项提到 `AGENTS.local.md`**：该载体已不存在，D57 关于"不登记可导出数量"的结论仍现行，
    登记位置改由本节与 §5.6 承担（旧条目不改写，见 §4.3.3）。

- **相关**：D27 / Q26（WSL 测试环境选型）、D57（不登记可导出内容）、D60（改测试机配置需客户授权的先例）、
  D61（测试门禁分层）、AGENTS.md §2.6（凭据绝不入库）。
