## 1. 本文件怎么用

- **读**：先在本索引定位编号 → 打开对应分片。**不要通读全部决策**
  （**2026-09-18 实测**：当日现行分片 51 个文件、合计 1316 行；快照 2 条在 `archive/`）。
- **写**：新增一条 = 新建 `docs/decisions/D<下一个编号>.md` + 在本索引对应域加一行 + 若推翻旧条则登记 §3 取代关系。
- **编号是外键，不是文件名**：`D47` 这样的编号在 Rust 注释里出现 **225 处 / 33 个文件**，
  是跨语言回溯"为什么这样写"的锚点。**永不重排、永不复用、永不改号**；
  条目乱序（如 D25/D26 晚于 D29 落盘）也不要为了"看着整齐"去重编号。
- **推翻旧结论的规矩不变**（AGENTS.md §4.3.3）：不改旧条目正文，新增一条并在 §3 登记取代关系。
- **三种状态**：`现行` / `部分失效`（正文有段落已被取代，见 §3）/ `快照`（整条机制已移除，
  原文躺在 `docs/decisions/archive/`，**不要按现行设计实现**）。

## 4. 拆分说明（2026-09-18）

- **为什么拆**：单文件长到 1262 行 / 92 KB，接手的 Agent 一次读取即吞掉全量；
  且**已被移除的机制原文**与现行结论混排，容易被当成现行设计去实现。
- **拆成**：本索引 + `docs/decisions/D<n>.md`（现行分片，条数以 §2 索引为准）+
  `docs/decisions/archive/D<n>.md` 共 **2 条快照**（D37、D44，两者机制均已被 D49 移除）。
  拆分脚本当时切出 49 条现行 + 2 条快照，D52 起改按"新决策 = 新分片"的流程补写。
- **正文无损**：分片由脚本逐字搬运，994 行正文逐行比对命中、两侧行数一致；
  仅相对链接按目录层级加了 `../` 前缀（7 处）。
- **拆分时同步修正的失真**：若干条目开头标注的"待决 / 待办 / 依赖保留"等状态已与代码不符，
  已按 AGENTS.md §4.3.4「状态要真实」就地改正到各分片正文（**现行结论以分片为准，此处不复述**）。
- **归档判据**：只有**整条**机制被明确写为"已整体移除"的才进 `archive/`
  （D37、D44，均见 D49）；**部分失效不搬**——整条搬走会连带丢掉现行结论，只在索引与本表标注。
