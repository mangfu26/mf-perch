# 更新检查：Gist 清单格式

> 对应决策 D23 / D42，问题 Q21 / Q34。
> 应用从**可配置的 URL** 读取一个 JSON 版本清单，发现新版本时提示用户去下载。

---

## 1. 默认源与维护方式

应用**内置了默认更新源**（D42），开箱即可检查更新，用户无需填写任何地址：

```
https://gist.githubusercontent.com/mangfu26/311c09b123911b6a4860483a645a4eb0/raw/mf-perch-update.json
```

维护者要做的只有一件事：**改 Gist 内容**（地址不变，用户即收到更新）。

- 必须使用**不带修订号（SHA）**的 raw 地址：`.../raw/<文件名>`。
  带 SHA 的形式（`.../raw/<一长串SHA>/<文件名>`）会钉死在某一版，改了 Gist 也没人看得到；
- 地址一旦发布就**别换**：内置默认值只能在发新版时修改，老版本用户需手动改设置
  （这正是保留"可覆盖"入口的价值）；
- 设置页「更新源地址」默认显示内置地址，可被用户覆盖，并有「恢复默认」按钮。

---

## 2. 清单格式

```json
{
  "version": "0.2.0",
  "notes": "本次更新内容，支持多行。",
  "pub_date": "2026-09-15T10:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "url": "https://github.com/mangfu26/mf-perch/releases/download/v0.2.0/mf-perch_0.2.0_x64.msi",
      "sha256": "安装包的 SHA256（可选，供用户核对）",
      "size": 12345678
    }
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `version` | ✅ | 最新版本号。语义化版本，允许带 `v` 前缀（如 `v0.2.0`） |
| `notes` | — | 更新说明，界面会原样展示（支持 `\n` 换行） |
| `pub_date` | — | 发布时间（RFC3339） |
| `platforms` | — | 各平台安装包；键名为平台标识 |
| `platforms.<键>.url` | ✅（若提供该平台） | 安装包下载地址 |
| `platforms.<键>.sha256` | — | 安装包 SHA256，界面会展示供用户核对 |
| `platforms.<键>.size` | — | 文件大小（字节） |

### 平台标识

当前版本使用 `windows-x86_64`。将来支持其他平台时，对应的键为：

| 平台 | 键名 |
| ---- | ---- |
| Windows x64 | `windows-x86_64` |
| Windows ARM64 | `windows-aarch64` |
| macOS Apple Silicon | `darwin-aarch64` |
| macOS Intel | `darwin-x86_64` |
| Linux x64 | `linux-x86_64` |

`platforms` 中缺少当前平台的条目时，应用**仍会提示有新版本**，
但没有下载按钮，会引导用户去仓库 Release 页自行查找。

## 3. 更新时的行为

| 情况 | 应用表现 |
| ---- | ---- |
| 远端版本 **高于** 本地 | 提示新版本，展示更新说明与下载按钮 |
| 远端版本 **等于** 本地 | 提示"已是最新版本" |
| 远端版本 **低于** 本地 | 判为最新——**不会提示降级**（避免开发版被诱导降级） |
| 版本号无法解析 | 判为检查失败并给出原因，**不会误报有新版本** |
| 用户点了「忽略此版本」 | 该版本不再提示；出现更新的版本时会重新提示 |
| 网络不通 / 地址错误 | 自动检查**静默失败**（不打扰用户）；手动检查会明确告知原因 |

**不会自动下载或安装**：只提示，由用户点击按钮打开下载页。

---

## 4. 注意事项

- **清单必须包含 `version`**（唯一必填字段），且用**不带 `v` 前缀**的写法
  （如 `0.1.0`）：解析容忍 `v`，但"忽略此版本"是字符串精确比对，带前缀会对不上；
- **`sha256` / `size` 不要填占位文字**：它们会原样展示给用户核对，
  填"待补充"这类文字等于给用户看假校验值——**要么填真实值，要么整个字段删掉**（两者都可选）；
- **首发时清单版本应等于应用版本**（如都是 `0.1.0`），否则所有用户一装上就被提示更新，
  而对应的 Release 可能还不存在；
- **发版顺序**：先发布 Release（确保下载地址可用），再更新 Gist。
  反过来的话，用户会被引导到一个还不存在的页面。
- **Gist 需人工维护**：这是选择 Gist 方案的已知代价（D23 已记录）。
  忘记更新 Gist 的表现是"用户一直收不到更新提示"，排查时先查这里。
- **检查频率**：自动检查有 24 小时缓存，不会每次启动都请求。
- **关闭自动检查**：用设置页的「启动时自动检查更新」开关；
  把更新源清空只是回退到**内置默认地址**，不等于关闭检查（D42）。
- **已实测**：该 Gist 的 raw 地址对应用的抓取方式（禁用重定向、5 秒超时、
  1 MiB 上限、带 User-Agent）返回 200 且不跳转（2026-09-12 验证）。

## 5. 发版检查清单

`sha256` 与 `size` **只能在构建出安装包之后才拿得到**（本地 `pnpm tauri build`，
或将来接上 CI 发布流程）。逐项核对：

| # | 事项 | 怎么取/怎么核 |
| ---- | ---- | ---- |
| 1 | 构建安装包 | `pnpm tauri build`（产物在 `src-tauri/target/release/bundle/`） |
| 2 | `sha256` | `Get-FileHash -Algorithm SHA256 <安装包>`（Windows）/ `sha256sum <安装包>` |
| 3 | `size` | 文件字节数：`(Get-Item <安装包>).Length` / `stat -c %s <安装包>` |
| 4 | 安装包**文件名** | 必须与清单 `platforms.windows-x86_64.url` 末段**完全一致**（大小写、版本号都要对） |
| 5 | Release **tag** | 必须与 URL 中的 tag 段一致（如 `v0.1.0`），否则链接 404 |
| 6 | 顺序 | **先发 Release，再改 Gist**；改完用应用手动「检查更新」验证一次 |
| 7 | 版本一致性 | 清单 `version` 高于用户本地版本才会提示；首发应**等于**本地版本，避免一装上就催更新 |

> **未拿到真实值之前**：`sha256` / `size` 直接**删掉**（两者可选），
> 不要留占位文字。留占位在当前不影响任何人（版本相同 → 判为"已是最新"，
> 用户看不到），但一旦清单版本高于用户版本，用户就会看到那串占位文字。
