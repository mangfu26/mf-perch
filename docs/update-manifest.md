# 更新检查：Gist 清单格式

> 对应决策 D23，问题 Q21 / Q34。
> 应用从**可配置的 URL** 读取一个 JSON 版本清单，发现新版本时提示用户去下载。

---

## 1. 你需要做什么

1. 在 GitHub 创建一个 **Gist**，内容为下面的 JSON；
2. 取该 Gist 的 **raw 地址**（形如 `https://gist.githubusercontent.com/<用户>/<id>/raw/<文件名>`）；
3. 在应用的「设置 → 关于 → 更新源地址」中填入该地址并保存。

之后应用启动时会后台检查更新（默认开启自动检查，可关闭），
用户也可在设置页手动点击「检查更新」。

---

## 2. 清单格式

```json
{
  "version": "0.2.0",
  "notes": "本次更新内容，支持多行。",
  "pub_date": "2026-09-15T10:00:00Z",
  "platforms": {
    "windows-x86_64": {
      "url": "https://github.com/mangfu26/mf-perch/releases/download/v0.2.0/mf-perch_0.2.0_x64.msi",
      "sha256": "安装包的 SHA256（可选，供用户核对）",
      "size": 12345678
    }
  }
}
```

### 字段说明

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `version` | ✅ | 最新版本号。语义化版本，允许带 `v` 前缀（如 `v0.2.0`） |
| `notes` | — | 更新说明，界面会原样展示（支持 `\n` 换行） |
| `pub_date` | — | 发布时间（RFC3339） |
| `platforms` | — | 各平台安装包；键名为平台标识 |
| `platforms.<键>.url` | ✅（若提供该平台） | 安装包下载地址 |
| `platforms.<键>.sha256` | — | 安装包 SHA256，界面会展示供用户核对 |
| `platforms.<键>.size` | — | 文件大小（字节） |

### 平台标识

当前版本使用 `windows-x86_64`。将来支持其他平台时，对应的键为：

| 平台 | 键名 |
| ---- | ---- |
| Windows x64 | `windows-x86_64` |
| Windows ARM64 | `windows-aarch64` |
| macOS Apple Silicon | `darwin-aarch64` |
| macOS Intel | `darwin-x86_64` |
| Linux x64 | `linux-x86_64` |

`platforms` 中缺少当前平台的条目时，应用**仍会提示有新版本**，
但没有下载按钮，会引导用户去仓库 Release 页自行查找。

---

## 3. 更新时的行为

| 情况 | 应用表现 |
| ---- | ---- |
| 远端版本 **高于** 本地 | 提示新版本，展示更新说明与下载按钮 |
| 远端版本 **等于** 本地 | 提示"已是最新版本" |
| 远端版本 **低于** 本地 | 判为最新——**不会提示降级**（避免开发版被诱导降级） |
| 版本号无法解析 | 判为检查失败并给出原因，**不会误报有新版本** |
| 用户点了「忽略此版本」 | 该版本不再提示；出现更新的版本时会重新提示 |
| 网络不通 / 地址错误 | 自动检查**静默失败**（不打扰用户）；手动检查会明确告知原因 |

**不会自动下载或安装**：只提示，由用户点击按钮打开下载页。

---

## 4. 注意事项

- **发版顺序**：先发布 Release（确保下载地址可用），再更新 Gist。
  反过来的话，用户会被引导到一个还不存在的页面。
- **Gist 需人工维护**：这是选择 Gist 方案的已知代价（D23 已记录）。
  忘记更新 Gist 的表现是"用户一直收不到更新提示"，排查时先查这里。
- **检查频率**：自动检查有 24 小时缓存，不会每次启动都请求。
- **未配置更新源时不发请求**：留空即完全关闭自动检查，不会产生无意义的网络请求。
- **缓存与忽略记录**存在本地数据库中，换机器后需重新设置更新源。
