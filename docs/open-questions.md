## 已确认结论

> 每条一行：一句话结论 + ADR 编号；结论正文见 `docs/decisions/D<编号>.md`，此处不复述。

### Q1 — 目标 MCP 客户端与传输方式
- 结论：只实现 MCP Streamable HTTP（官方 `rmcp` SDK），不做 stdio 与桥接 → D1

### Q2 — MCP 端点暴露与鉴权
- 结论：默认仅监听 `127.0.0.1`、可开远程；Bearer Token 鉴权；端口 50001 起迭代并持久化 → D2 / D30

### Q3 — 终端会话模型
- 结论：见 D3（环境加载策略见 D4）

### Q4 — 命令执行时序模型
- 结论：同步 + 异步双模式与状态查询，同终端串行排队；状态枚举以 D50 为准 → D5 / D50

### Q5 — 凭据与数据存储
- 结论：见 D6

### Q6 — 首发平台
- 结论：见 D8

### Q7 — SSH 库选型
- 结论：见 D9

### Q8 — 主机密钥校验策略
- 结论：见 D10

### Q9 — MVP 的 SSH 高级能力范围
- 结论：ProxyJump 已移出首发（对外不得声称支持），SFTP / 端口转发进二期 → D11 / D45

### Q33 — sudo 提权三模式
- 结论：`deny` / `ask` / `auto` 三档 + 双通道提权，一期全部实现 → D47 / D48 / D49

### Q36 — ask 模式下的重复询问
- 结论：问题成因随旧投递机制消失，"拒绝只问一次"的记忆已删除 → D49（D44 已转快照）

### Q37 — 未解锁主密钥时能否保存主机
- 结论：保持必须先解锁，不做延迟取密钥 → D56（背景见 P5）

### Q10 — SSH 私钥导入
- 结论：见 D12

### Q11 — 终端数量与并发上限
- 结论：见 D13

### Q12 — 命令历史保留策略
- 结论：按时间保留（默认 30 天，可配至永久），不设条数上限；归档终端永久保留 → D14

### Q13 — 前端技术栈
- 结论：见 D15（xterm.js 未采用，依赖已移除）

### Q14 — 应用形态
- 结论：见 D16

### Q15 — 使用模型
- 结论：见 D17

### Q16 — 界面语言与 i18n
- 结论：见 D18

### Q17 — 命令历史审计能力
- 结论：时间线 + FTS5 全文搜索 + 筛选；导出改为不做 → D19 / D31

### Q18 — 归档终端的恢复
- 结论：见 D20

### Q19 — 删除终端时历史一并删除
- 结论：见 D21

### Q20 — 长命令完成的通知

### Q21 / Q34 — 更新检查与版本源

### Q22 / Q35 — 视觉风格与主题

### Q29 — 提交身份邮箱

### Q39 — 「发现新版本」的下载入口

### Q40 — README LOGO
- 结论：复用应用图标导出 `docs/assets/logo.png`，不做横版字标（尚无 ADR 落点，见 `design/theme-spec.md` §7）

### Q41 — 入口是否登记条目区间
- 结论：不写；入口只索引"这块是什么"，条目自行到被索引文件查 → D59 / D57

### Q42 — 特权身份免提权
- 结论：让"提权"对特权身份消失，由人在凭据上声明 `credentials.is_privileged` → D60
